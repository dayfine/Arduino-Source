M4: outstanding quest retry budgets

Run from the repository root:

```sh
c++ -std=c++23 -Wall -Wextra -Werror -ISerialPrograms/Source tests/pokemon_sv/test_bbq_quest_retries.cpp -o /tmp/bbq-m4-tests
/tmp/bbq-m4-tests
python3 -m unittest discover -s tests/pokemon_sv -p test_bbq_retry_dispatch.py -v
```

NUM_RETRIES=1 permits two total attempts per outstanding quest, not two per batch.
Reordered/uncertain boards and other completions do not replenish it. Completion
or absence from a fully read four-slot board retires the old budget. A three-slot
board is conservatively insufficient to infer removal. Identical quests replaced
between observations cannot be distinguished by the existing enum-only reader.

If all runnable quests are exhausted, stop clearly without spending BP; failure
actions belong to M6. This PR does not change navigation or OCR certainty rules.

Deterministic dispatch replay

The Python suite compiles the actual production farmer loop and
process_and_do_quest function bodies against the real retry-state header and quest
enum. OCR board reads, route execution, policy selection, hardware, navigation,
and statistics services are simulated. The loop and attempt algorithm are not
copied into test code; no test hooks are added to production sources.

With one retry, the main replay observes:

- Batch 1: Sneak-up fails twice, then Make TM completes.
- Batch 2: exhausted Sneak-up is filtered out, Travel 500 completes.
- Batch 3: only exhausted Sneak-up is runnable; farmer stops before dispatch.
- Total: 2 Sneak-up attempts, 2 other completions, 0 paid fallback invocations.

Seven tests cover that sequence, reordered boards, a partial board omitting the
failed quest, a four-slot board containing an unknown slot, confirmed removal
from a complete board followed by a new budget, zero retries, and a mutation
control. Disconnecting the session retry state (per-call budgets) makes the
replay fail on an unexpected third attempt. This verifies dispatch wiring and
stop behavior; it does not exercise OCR, controller actions, or reroll policy.

Live validation, 2026-10-21

The corrected isolated M4 profile completed Auto Battle 10, Make TM, and Polar
photo. All three succeeded on their first attempt. Stopping the run logged
"Stats successfully saved!" after creating the profile's initially missing stats
file. The quest cap is checked between batches, so a fourth quest started before
the manual stop; three completions were recorded. The earlier profile mistakenly
mapped unsupported Pickup to Auto-10 Skip, which triggered legacy paid rerolls;
that profile setup was corrected without changing production code.

Normal live quest progress and stats persistence are checked. Persistent failure
retention is covered by replay, not yet by a live exhausted-budget event. A future
live failure test needs a reliably missing-target Sneak-up quest plus another
runnable quest: with one retry, confirm two total attempts, progress on the other
quest, and no third dispatch across subsequent batches. Record board/BP before
and after. No additional Switch run is required for this replay-only update.
